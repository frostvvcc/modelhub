## 〇、先建立一个判断框架：什么叫"深度使用"

面试官区分"调包侠"和"真懂的人"，靠的就是下面这个深度阶梯。同一个技术，你在哪一层，面试表现天差地别。

| 层级 | 状态 | 面试表现 |
|------|------|---------|
| **L1** | 会调 API、能跑通 | "我用了 ChromaDB 做向量检索" —— 一问就穿 |
| **L2** | 懂每步在干什么、参数啥意思 | 能解释代码，但问"为什么这么选"就卡 |
| **L3** | 知道它什么情况会出问题、怎么排查 | 能讲踩过的坑 —— **实习及格线** |
| **L4** | 做过量化评估 / 性能调优 / 有 A-B 取舍 | "我测过 alpha=0.6 召回率最高" —— **碾压同期实习生** |
| **L5** | 改过源码 / 有自己的改进 / 能对比替代方案 | 社招高级才要求，实习有一项就是惊喜 |

**大厂 AI 实习面试的潜规则**：你的项目会被逐环节深挖。面试官不在乎你用了多少技术，在乎你对**用了的技术**能讲到第几层。**广度是简历的敲门砖，深度才是 offer 的决定项。**

## 三、核心武器逐个深挖（附具体代码任务）

### 3.1 RAG 检索管线 —— 最高性价比的深挖点

**你已经有的（真东西，要讲出来）**：
- 向量检索 + BM25 混合检索，RRF 融合（`retrieval.py`）
- 三种分块策略、距离函数自适应、BM25 的 LRU 缓存、jieba 降级

**面试官会戳穿你的地方**：

> **"你怎么知道你的检索效果是好的？"** —— 你目前答不上，因为**没有任何量化评估**。

这是你和 L4 之间唯一的、也是最致命的差距。

#### 🎯 深挖任务 1（最高优先级，1 周内做完）：建 RAG 评测体系

```
1. 从你的知识库里造 30-50 个「问题 → 标准答案文档」对（评测集）
2. 写一个评测脚本，对每个问题跑检索，计算：
   - Recall@k：top-k 里有没有命中标准文档
   - MRR (Mean Reciprocal Rank)：标准文档排在第几位
   - 命中率 Hit Rate
3. 把这些参数跑成对比表：
   - alpha = 0.3 / 0.5 / 0.7 / 0.9（向量vs BM25 权重）
   - chunk_size = 400 / 800 / 1200
   - RRF k = 30 / 60 / 100
   - n_results = 3 / 5 / 10
```

**做完后你能在面试说**：*"我建了 50 条评测集，测出 alpha=0.6 时 Recall@5 最高达到 0.84，chunk_size 从 800 降到 400 反而召回下降因为语义被切碎了。"*

> 这一句话，直接从 L2 跳到 L4，**碾压 95% 的实习候选人**——因为绝大多数人的 RAG 项目只到"我实现了"，从没"我验证了"。

#### 🎯 深挖任务 2：接入 Reranker（重排序）

你的代码**没有 reranker**（已确认）。工业级 RAG 是「粗排 100 条 → 精排取 5 条」两阶段。

```
1. 接 bge-reranker-base（开源、轻量）或用 LLM 做 rerank
2. 流程：混合检索取 top-20 → reranker 重排 → 取 top-5
3. 用任务 1 的评测集，对比"加 rerank 前/后"的 MRR 提升
```

**面试加分**：能讲清"为什么要两阶段检索"（召回与精度的权衡——粗排保召回，精排保精度）。

#### RAG 必背八股（实习高频）
- **怎么减少幻觉？** → grounding（你有 grounded_ratio）、citation 引用、检索不到就明说
- **检索不准怎么办？** → query 改写、HyDE、多路召回、rerank
- **chunk 怎么切最好？** → 没有银弹，取决于文档结构；语义完整 vs 检索精度的权衡
- **长文档怎么处理？** → 父子分块、small-to-big（检索小块、喂大块给 LLM）

### 3.2 Agent / Function Calling —— 第二张王牌

**你已经有的**：ReAct 循环、状态机编排、Trace 追踪、动态工具注册（`engine.py`、`tools.py`）

**必须修复的硬伤（面试官一眼看穿）**：

#### 🔴 硬伤 1：假流式（`engine.py:204-208`）
```python
# 现在：先拿完整响应，再逐字符 yield，假装流式
CHUNK_SIZE = 4
for i in range(0, len(accumulated_content), CHUNK_SIZE):
    yield AgentEvent(type="token", data={"content": accumulated_content[i:i+CHUNK_SIZE]})
```
**改成真流式**：最终回答轮用 `stream=True`，边生成边 yield。否则用户等半天突然全出，体验差，且 `SimpleStreamEngine` 是真流式形成自相矛盾。

#### 🔴 硬伤 2：串行工具调用（`engine.py:142`）
```python
for tc in message.tool_calls:   # 串行！3个工具=3倍耗时
    result = await tool.execute(...)
```
**改成并行**：`asyncio.gather` 同时执行多个工具调用。这正好能讲你的 async 功底。

#### 🔴 硬伤 3：eval 安全洞（`tools.py:186`）
```python
result = eval(cleaned, {"__builtins__": {}}, self.SAFE_FUNCTIONS)  # 可逃逸！
```
**改成** `ast.literal_eval` 或自写表达式解析器。AI 面试官也是工程师，看到 eval 直接扣分。

#### 🎯 深挖任务 3：加反思 / 重试机制
工具执行失败现在直接返回 `{"error": ...}`。加一个"工具失败 → LLM 决定重试或换工具"的逻辑，这就是 Agent 的"自愈"能力。

#### Agent 必背八股
- **ReAct vs Plan-and-Execute 区别？**（边想边做 vs 先规划再执行）—— 高频
- **Agent 怎么防止死循环？**（你有 max_iterations=5 兜底，能讲）
- **多个 Agent 怎么协作？**（你现在单 Agent，能讲扩展思路）
- **Function Calling 的原理？**（LLM 输出结构化 JSON，你解析后执行，结果喂回）

### 3.3 向量数据库（ChromaDB）—— 必须补原理

**你目前只是 L1**：调了 `query`/`get`，不懂底层。面试必问：

- **HNSW 索引原理是什么？** ← 向量库核心算法，**必背**。一句话：分层可导航小世界图，高层粗找、底层精找，用图的跳跃实现近似最近邻（ANN）的对数级查询。
- **为什么用近似检索（ANN）不用精确检索？** ← 亿级向量精确算 O(n) 太慢，ANN 牺牲一点精度换百倍速度。
- **为什么选 ChromaDB 不用 Milvus/Qdrant？** ← 准备好对比：ChromaDB 轻量、Python 原生、适合中小规模 demo；Milvus/Qdrant 适合生产级亿级数据。能说出 ChromaDB 的局限（单机为主、不适合超大规模）反而显得你懂。

#### 🎯 深挖任务 4：写一份选型对比（半天）
ChromaDB vs Qdrant vs Milvus 的维度对比（性能、规模、部署、生态），放进项目文档。面试被问"为什么选 X"时直接有体系化回答。

### 3.5 Python async —— 你的隐藏加分项

你的真异步链路（`async_llm.py`、`async_llm_pool.py`、全 async 路由）是实打实的功底，**主动讲出来**：
- asyncio 事件循环、协程 vs 线程 vs 进程
- 你的 LLM 客户端连接池用了双重检查锁定（`async_llm_pool.py`）—— 能讲并发安全

#### 🎯 深挖任务 5：修一个真 bug，讲一个真故事
`cache.py` 在 **async 函数里用了同步的 redis client**（`redis.Redis().get()`），会**阻塞事件循环**——这是 asyncio 的经典误用。

```python
# cache.py 现状（async_wrapper 内）—— 同步阻塞调用
redis_client = redis.Redis(connection_pool=redis_pool)
cached = redis_client.get(cache_key)   # 阻塞 event loop！
```

改成 `redis.asyncio`（异步客户端）。修完你就能在面试讲：*"我发现权限缓存在异步接口里用了同步 Redis 客户端，会阻塞整个事件循环，我换成 redis.asyncio 后并发吞吐明显改善。"* —— 这是教科书级的"踩坑 + 排查 + 解决"故事，面试官最爱听。

## 五、面试表达策略（实习阶段：能讲深 ≈ 真的深）

实习面试，**把项目讲清楚讲深入，比技术栈堆得多更重要**。准备一个 STAR 式的项目讲述：

1. **一句话定位**："我做了一个面向高校的 RAG 智能问答平台，自研了混合检索管线和 ReAct Agent 引擎。"
2. **主动暴露你最深的环节**：直接抛"混合检索 + RRF 融合"和"评测体系"，把面试官引到你的强项区。
3. **每个技术准备一个"为什么"**：为什么混合检索、为什么 alpha=0.6、为什么 RRF 不用加权求和——**"为什么"才是深度**。
4. **准备 2-3 个踩坑故事**：假流式怎么发现的、cache 阻塞 event loop 怎么排查的、检索不准怎么调优的。
5. **诚实面对不足**："这个项目还没做 reranker 和大规模压测，如果上生产我会先补这两块"——**会讲不足，本身就是成熟度的体现**。
