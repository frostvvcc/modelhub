## 修复详情

### P0-1: Cross-Encoder 幽灵依赖 → 真实依赖

**改动：** `requirements-fastapi.txt` 新增 `sentence-transformers>=3.0.0`

**效果：** `BAAI/bge-reranker-v2-m3` 可以被实际加载，三级 Reranker 的 Level 2 Cross-Encoder 不再空转 fallback 到 LLM。

---

### P0-2: Context Budget 字符级 → Token 级

**改动：** `chat_service.py` → `_build_context_blocks()`

**核心变更：**
- 参数从 `max_context_chars` 改为 `max_context_tokens`
- 新增 `_count_tokens()` 方法，调用 `agent/memory.py` 的 tiktoken 计数
- 截断逻辑改为按 token 累加，通过 `ratio = available_tokens / content_tokens` 计算裁剪比例
- 向后兼容：如果 model_config 只有 `max_context_chars`，自动 `//2` 转换为 token 估算

---

### P0-3: E2E 评测解析失败 → 多策略 JSON 提取 + 重试

**改动：** `eval/e2e_eval.py` 完全重写

**核心变更：**
1. `_extract_json()` 三级解析策略：
   - 优先提取 ` ```json ... ``` ` 代码块
   - 次选提取裸花括号 `{...}`
   - 兜底正则匹配 `"dim": score` 模式
2. `judge_answer()` 添加最多 2 次重试
3. 结果维度值强制 clamp 到 [1, 5]
4. 报告新增 `parse_failures` 和 `parse_success_rate` 字段

---

### P0-4: 消融实验无统计显著性 → Bootstrap 95% CI

**改动：** `eval/ablation.py`

**核心变更：**
- 新增 `_bootstrap_ci()` 函数：1000 次有放回重采样，计算 95% 置信区间
- 消融报告每个参数的最优值附带 `best_recall@5_ci95`（含 mean, ci_lower, ci_upper, n）
- 报告开头标注样本量 N 和统计方法
- 输出新增 NDCG@5

---

### P1-1: 缺少 NDCG 指标

**改动：** `eval/metrics.py` + `eval/runner.py`

- `ndcg_at_k()` 实现 Binary Relevance NDCG（DCG / IDCG）
- `evaluate_retrieval()` 输出新增 `ndcg@5` 和 `ndcg@10`
- 消融报告同步输出 NDCG

---

### P1-3: GraphRAG A/B 对比评测

**新建：** `eval/graphrag_eval.py`

- 对同一组 query，分别用「有 GraphRAG 三元组上下文」和「无 GraphRAG」生成回答
- 用 e2e judge 四维评分两组回答
- 输出各维度 delta 和自动结论（"提升/退化/无显著影响"）

---

### P1-4: Reranker 消融

**新建：** `eval/reranker_eval.py`

- 运行时动态切换 `RAG_RERANK_MODE`（off / cross_encoder / llm）
- 用 `enhanced_query()` 走完整管线（含 rerank 阶段）
- 输出 Recall@5 / MRR@5 / NDCG@5 对比

---

### P1-5: Grounding 准确率评测

**新建：** `eval/grounding_eval.py`

- 内置 8 组标注数据（16 条 claim），覆盖 supported / unsupported / contradicted
- 调用 `verify_grounding()` 获取预测 verdict
- 计算整体 accuracy + 每类 Precision / Recall / F1

---

### P2-1: Agent REFLECTING 空壳 → 真正反思 Prompt

**改动：** `app/services/agent/engine.py`

- 在 REFLECTING 状态注入系统消息，指导 LLM 审查工具结果是否充分
- 包含三点检查：信息是否足够、是否有失败需重试、是否需要补充调用
- 如信息充分则直接生成回答，不充分则继续调用工具

---

### P2-3: PDF 表格结构化改进

**改动：** `app/services/rag/document_parser.py`

- 合并单元格处理：空 cell 继承上一行同列的值
- 多行内容处理：cell 内换行替换为空格
- 管道符转义：cell 内 `|` 转为 `\|` 避免破坏 Markdown 结构
- 空行过滤：全 None/空的行直接跳过
- 列数对齐：以最长行为准

---

### P2-4: RAG 运行时质量监控

**新建：** `app/services/rag/monitor.py`

- `RAGQueryMetrics` 数据类：记录各阶段 latency、相似度、grounded_ratio、rerank 是否改变 top1
- `RAGMonitor` 滑动窗口（默认 200 条）统计器
- `RAGTimer` 上下文管理器，精确测量各阶段耗时
- 集成到 `retrieval.py` → `enhanced_query()` 主链路
- 新增 `GET /vector/rag/monitor` 端点（仅管理员可访问）

**监控维度：**
- Latency: avg/p95 total, avg vector/bm25/rerank/grounding
- Quality: avg top1 similarity, avg grounded ratio, rerank change rate, low confidence rate
